# Maintainer commentary: work with the user

**Status:** Inactive candidate. This is human review commentary, not additional agent instructions. [SKILL.md](SKILL.md) contains the proposed load. The [analysis](../../../collaboration-guidance-design-2026-10-05.md) owns incident grounding and evidence limits.

## Intended use

Sometimes neither the user nor the agent has a settled goal or a workable problem yet. They need to develop these together before useful autonomous work becomes possible. Necessary user judgments can also remain unsettled even when much of the work is already clear.

Efficient interaction makes that development feasible within time, tokens, attention, frustration tolerance and agent context coherence. It belongs inside problem structuring. Focused conversations should produce useful understanding, not merely fewer or shorter messages. Some decisions must wait for findings, so complete upfront clarification is not promised.

## Why this trigger

The description starts with the abstract condition: making work ready for reliable autonomy requires joint development. The examples help an agent recognize that condition; they are not an exhaustive list to maintain whenever a new symptom appears. The routine-task boundary prevents unnecessary interviews.

This is a proposed encounter rule, not evidence that agents select or follow it reliably. Internal investigative uncertainty alone does not establish a need to question the user. Ending despite already having a useful authorized next action is a continuation problem, not evidence that this trigger applies.

## Review question

Does the abstract condition identify the situations where joint work is needed, without assuming a pre-existing intent or pulling clear autonomous tasks into conversation?
