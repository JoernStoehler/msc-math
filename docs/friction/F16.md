# F16 Human navigation and mixed audiences

**Observation:** Jörn reported that the expanded friction Page was hard to navigate and scattered information. The agent had replaced a compact table with long individual records and then proposed another summary, adding reading and synchronization burden. This does not establish that Pages is worse than the next best alternative.

**User decision:** Pages own persistent views intended for Jörn and closely integrated with ChatGPT. GitHub owns durable workspace content collaboratively maintained by agents, which Jörn normally need not inspect. Conversations and comments are inputs; agents update records and the human overview without requiring a separate routine request.

**Current outcome:** mitigated by the adopted surface split. Fifteen existing records and trial evidence were committed to docs/friction on main. The Page now opens with a five-row overview and a compact disposition summary; its pre-migration detail is marked frozen and its section headings are collapsed by default. Page readback verified these facts. The structural edit rejection and workaround are tracked in F09.

**Limits and next test:** rendered client presentation and a later independent session's routine update through repository and Page remain unverified. Evaluate total user attention, agent calls/retries, freshness and maintenance against the best working alternative before adding a custom service or UI. No acknowledgement session or user file review is assigned.
