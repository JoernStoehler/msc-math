# Design notes

Jörn asked for problem and goal development together, with useful interaction as an enabling condition: time, tokens, attention, frustration tolerance and context coherence can run out before the problem becomes workable. See [the incident inventory](../../../../meta-topics/agent-workflow/collaboration-guidance-design-2026-10-05.md). It distinguishes exploratory framing, concrete review, independent strategy analysis and continuation failures; none proves this guidance would have prevented them.

The abstract readiness trigger precedes examples, following Jörn's maintenance preference. The joint-only `work-with-user` candidate lost independent agent-resolvable decomposition; review restored that capability under `problem-structuring`. Loading this skill does not require questioning the user. Upstream maps, probability logs and numbered claims are deliberately optional methods, not universal rituals. Existing project coordination owns material state.

Focused synchronous discussion is useful when decisions can be prepared together; later discoveries can require later discussion. One combined communication/structuring skill remains an alternative if observed missed transitions outweigh unnecessary loading. Behavioral selection, application and benefit remain untested.

## Trigger rationale and review

The trigger describes readiness for autonomous work before listing recognition examples. It covers developing goals as well as unresolved decisions in otherwise clear work; it assumes neither a settled, queryable intent nor a need to involve the user in every uncertainty. Clear routine tasks need no structuring interview. Ending while a useful authorized next action is already available is a continuation failure, not evidence that more structuring is needed.

Open review question: does this condition catch work needing structuring without pulling clear autonomous tasks into unnecessary conversation? Successful discovery does not establish reliable selection or application.
