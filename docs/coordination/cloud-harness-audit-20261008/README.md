The [October synthesis](../../knowledge/session-failures-2026-10-03.md) routes precise episodes to the retained traces. Its distinctions explain more than a generic complaint about tone:

Some next actions were already available; another required decomposition that a separate agent later supplied. Memory or an owner label alone did not produce continuation.
2. **Review checks the wrong proposition.** A supervisor observed a completed component and accepted it despite the broader gap. More frequent polling would not fix the judgment. The inspected native transport also could not wake an idle root; watcher correctness and effective recovery are distinct requirements.
3. **Agent analysis is exported as a question to Jörn.** Agents asked him to reconstruct known facts, select from poorly supported alternatives or assess an object without its necessary context. Shortness or multiple-choice presentation did not make those questions useful. The [timing evidence](../../history/session-postmortem-2026-10-04/REPORT.md#the-user-remained-the-recovery-mechanism) also records a rendered candidate arriving after the available PDF-review window.

Separate allocation reviews improved details while retaining a disputed staffing/integration assumption. More agents help only when they independently address the actual crux and their conclusions survive assembly.
5. **Documentation completion substitutes for behavioral repair.** Discovery, YAML/link checks, semantic review and human approval of wording each establish something useful, but not whether the agent will save Jörn the next intervention.

The newer [behavioral dispositions](../../history/skill-presweep-20261006/behavior-dispositions.md) contain one positive synthetic continuation result and subsequent live negative evidence: the same root again made unsupported evidence/cause claims and interpreted lost trust as permission to stop. The skills are not wholly untested, but reliable repair is not established. Some older summaries saying no forward evidence exists lag this newer record.

Useful current guidance includes independent investigation before user questions, preservation of parent work through corrections/acknowledgments, bounded delegation, and integration ownership. The audited bodies did not reveal a substantive instruction contradiction explaining the failures. Broader context/routing costs remain uncertain. A prior historical-reconstruction comparison found no demonstrated saving from adding a report packet; it does not establish that the current skills are harmful. Strongly reinforced model habits are a plausible hypothesis, but these traces establish decisions and consequences rather than a training-level cause or deliberate disregard. That uncertainty does not excuse the service failure or require waiting for a causal proof before testing improvements.

## Concrete next package

The most useful next work would establish an executable baseline and test ownership of the real workflow, rather than commission another broad rewrite:

1. Separate credential-free baseline setup from optional artifact and Sage setup; identify the intended cloud image and required runtime capabilities. Retain the reviewed replacement files in Git without indiscriminately committing the dirty tree or altering the separately governed config.
2. Provide a deliberate artifact-access contract and a private retention disposition for the local-only evidence. Fresh-cloud review delivery should have an available route rather than inherit workstation URLs as a capability promise.
3. Run a disposable clean checkout without Jörn's config, installed project skills or caches: focused Rust work, thesis build, then the selected artifact/exact subset. Treat this as staged coverage, not a reason to rerun all expensive producers.
4. On bounded realistic tasks, compare the current coordinator with a version receiving independent review of consequential questions, allocation and proposed completion *before* yielding. Give the reviewer the whole intended outcome and authority, not only the latest component or root's preferred alternatives. Its return identifies an unfinished parent obligation and concrete authorized next operation, or the exact necessary human input. The root owns acting or visibly presenting that input; a passing component review cannot close the broader obligation. This is a candidate treatment: reviewers can share blind spots, add latency, or produce advice the root ignores. Include a simple task where extra delegation/review should be skipped. Score completed outcomes, avoidable user interventions and elapsed time; use deterministic checks for mechanical failures.

The critical path includes root synthesis, serial review preparation and user availability. Splitting independent work and delegating integration can reduce it; increasing concurrency alone does not repair a poor comparison or an ignored result. Fresh reviewers should challenge the actual assumption and return an executable correction. They should not become another queue Jörn must supervise. Any larger evaluation or autonomous thesis programme remains separately selected; the assessment does not create a new small-task approval gate.
