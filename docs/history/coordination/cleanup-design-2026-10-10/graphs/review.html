1. Work dependencies

Blue: established workflowAmber: project-specific decisionPurple: synthesis / downstream useGrey/green: integration / review

Solid arrows: an input needed for acceptance. Dashed arrows: incremental information or coordination. Preparation and prompt expansion can start earlier. “Standard” describes the method, not guaranteed correctness or low effort. Diagrams retain readable text size; scroll horizontally as needed.

Amber decisions have useful fallback routes: preserve different validation policies behind adapters; consolidate only the supported proof claims; preserve the existing single-writer/schema contract if a broader change is unresolved. These hold up only dependent changes. New mathematical research and long dataset/certificate reruns are not hidden inside routine cleanup.

Cross-stream gates: Baseline fixtures are captured before accepting geometry/data changes; the KKT comparison tests use the reconciled convention. These cross-stream gates are compressed in the overview.

Shared writers: one geometry integrator controls the shared geometry files; the foundations manager integrates shared LaTeX imports/labels; the data manager controls schemas; the account manager assembles shared navigation. Parallel workers own distinct files or prepare patches for that owner. This prevents “parallel” from meaning concurrent edits to the same file.

2. Delegation and review

Root writes five compact seeds, not twenty long prompts. Each Sol manager expands its own seed, source context and worker prompts concurrently. A seed specifies the outcome, boundaries, source owners, tests, stopping point and receiving owner. Managers can spawn further bounded help; Luna can perform real routine refactors/debugging as well as search and extraction, with Sol reviewing the result.

Starting shape: five managers, roughly two to four active producers/helpers per branch, plus integration/observation. Reviews start when inputs exist; the account branch can split further by topic. This is an initial scheduling proposal, not a fixed cap or measured optimum. The approximately 99 worker slots include managers and nested descendants. Root allocates slots across branches; managers redistribute locally. Growth requires independent work and review capacity, not just spare slots.

CPU, memory, Cargo locks, artifact writers, benchmark isolation and integration queues also constrain concurrency. One build/benchmark owner schedules conflicting commands while reading, coding and prompt expansion continue. Numeric spending and runtime allowances remain launch inputs.

Astra receives one assembled candidate and reading packet: objective/coverage map; source-ordered changed-file list with reasons to read; contracts and proof assumptions; Sol review findings and dispositions; exact checks/fixtures; remaining gaps; and the fresh-agent writing-plan result. Astra can follow source trails or request missing context. Sol fixes findings, then returns one consolidated delta packet for targeted rereview. Summaries do not substitute for source inspection.
