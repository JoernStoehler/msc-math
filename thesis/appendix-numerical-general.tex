\paragraph{Soundness goal.}
The numerical algorithm must never report a capacity value
that is provably wrong: if the algorithm certifies a value,
that value must correspond to a genuine critical point of the
exact problem.
When the floating-point evidence is insufficient to determine
a predicate's truth value, the algorithm must acknowledge
the uncertainty rather than guess.

\paragraph{Three-valued predicates.}
We formalise this by allowing predicates to return
$\textsc{unknown}$ in addition to $\textsc{true}$ and
$\textsc{false}$.
A predicate~$\tilde P$ computed from floating-point data
is \emph{sound} if it satisfies:
\begin{align*}
  P \text{ true in exact arithmetic}
  &\;\Longrightarrow\;
  \tilde P \neq \textsc{false}, \\
  P \text{ false in exact arithmetic}
  &\;\Longrightarrow\;
  \tilde P \neq \textsc{true}.
\end{align*}
In other words, $\textsc{true}$ and $\textsc{false}$ are
reliable verdicts; $\textsc{unknown}$ means the numerical
evidence is inconclusive.
Not every predicate in the implementation needs this
treatment---many decisions (e.g.\ index comparisons,
loop bounds) are exact in floating-point arithmetic.
The three-valued framework applies to the predicates
whose evaluation involves numerical error, principally
the positivity predicate $\beta_i > 0$
(Section~\ref{app:svd-step}).

\paragraph{Impact on the algorithm's control flow.}
The exact algorithm has two kinds of decision points:
\begin{description}
\item[Inclusion decisions] (``unless $P$, skip''):
  The exact rule ``if $\lnot P$, skip $(S, \sigma)$''
  becomes ``if $\tilde P = \textsc{false}$, skip.''
  When $\tilde P = \textsc{unknown}$, the pair is kept
  (conservatively), since the exact~$P$ might be true.
  This means the numerical algorithm searches at least as
  broadly as the exact algorithm.
\item[Maximum tracking] (``find the largest admissible $Q$''):
  An admissibility predicate $A(\beta)$ (e.g.\ $\beta_i > 0$
  for all~$i$) becomes three-valued.
  The algorithm returns:
  \begin{itemize}
  \item the largest~$Q$ where $\tilde A = \textsc{true}$
    (the \emph{certified value}, a lower bound on the
    true maximum),
  \item all~$Q$ values above the certified value where
    $\tilde A = \textsc{unknown}$
    (the true maximum may be among these).
  \end{itemize}
  Candidates with $\tilde A = \textsc{false}$ are provably
  inadmissible and discarded; uncertain candidates at or below
  the certified value are irrelevant (the certified value already
  dominates).
\end{description}

\paragraph{Information flow.}
The three-valued predicates interact through a pipeline
of producers and consumers:
\begin{enumerate}
\item \textbf{KKT solving and near-singular dismissal}
  (Section~\ref{app:svd-step}).
  For each pair $(S, \sigma)$, the SVD solves the KKT system
  and detects near-singular systems.
  If a near-null direction has significant
  $\beta$-component, the pair is dismissed: its value
  is provably covered by a smaller pair
  (Algorithm~\ref{alg:near-singular-handling}).
  Otherwise, the SVD produces a computed coefficient
  vector~$\hat\beta$.
  Dismissal is a binary decision (not three-valued).
\item \textbf{Positivity classification.}
  The computed~$\hat\beta$ is classified by the positivity
  predicate $\tilde P_{>0}$
  (Section~\ref{app:svd-step}) into certified
  ($\textsc{true}$), inadmissible ($\textsc{false}$),
  or uncertain ($\textsc{unknown}$).
  Adjacency and directed adjacency
  (Section~\ref{app:polytope-combinatorics})
  filter the search space as binary decisions.
\item \textbf{Accumulated $Q$ maximum}
  (Section~\ref{app:accumulated-q-max}).
  The algorithm tracks the best certified
  and best uncertain candidates separately.
  Some $\textsc{unknown}$ verdicts are resolved
  \emph{late}: an uncertain candidate whose $Q$~value
  falls below the certified maximum is irrelevant
  regardless of its true admissibility.
  Only uncertain candidates \emph{above} the certified
  maximum require further attention.
\item \textbf{Unresolvable cases.}
  If an uncertain candidate dominates the certified maximum,
  \texttt{f64} precision is insufficient to determine the
  true capacity.
  The implementation currently reports an error in this case.
  A second pass with higher precision (exact rationals or
  extended-precision floats) could resolve the remaining
  $\textsc{unknown}$ verdicts, but this is not yet implemented.

\end{enumerate}
