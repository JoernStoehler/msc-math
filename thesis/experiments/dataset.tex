\subsection{The Dataset}
\label{sec:dataset}

We maintain a unified dataset of convex 4-polytopes with EHZ capacity values
computed by all applicable algorithms. This avoids redundant computation:
each polytope is processed once, and different experiments read different
columns of the same data.

\subsubsection*{Algorithms}

Two algorithms are implemented and tested:

\begin{enumerate}
  \item \textbf{HK2017} (Section~\ref{sec:main-result}): Applies to all convex
    4-polytopes. Exhaustive search over cyclic permutations of facet subsets,
    with adjacency-based pruning. Cost is exponential in the facet count~$F$.
    Two variants: \emph{pruned} (production) and \emph{unpruned} (reference,
    for cross-validation).

  \item \textbf{Billiard} (Section~\ref{sec:billiard}): Applies only to
    Lagrangian products $K_q \times_L K_p$ where both factors are convex
    polygons. Exploits the sigma structure lemma and a 3-bounce bound to
    restrict enumeration to polynomial cost.
\end{enumerate}

A third algorithm (tube) is planned but not yet implemented.

\subsubsection*{Polytope groups}

The dataset consists of overlapping groups. A polytope may belong to multiple
groups. Each group's existence is motivated by a specific experiment or
verification need.

\subsubsection*{Algorithm columns}

For each polytope, the dataset records:
\begin{itemize}
  \item Geometry: facet normals and heights (H-representation).
  \item Volume (computed via convex hull).
  \item \textbf{HK2017 pruned}: capacity, computation time, iteration count.
    Present for all polytopes with $F \le 14$.
  \item \textbf{Billiard}: capacity, computation time, iteration count, bounce
    count. Present only for Lagrangian products.
  \item \textbf{Agreement flag}: whether HK2017 and billiard agree within
    relative tolerance $10^{-8}$.
\end{itemize}

The HK2017 unpruned variant is additionally computed for a small subset of
base polytopes with $F \le 8$ during fixture generation
(Section~\ref{sec:correctness}). Its exponential cost without pruning makes
it infeasible for larger polytopes (see Section~\ref{sec:benchmark} for
timing data).

\subsubsection*{Data files}

The dataset is stored as JSONL files (one JSON object per line):
\begin{itemize}
  \item \texttt{polytopes.jsonl} --- \textsc{LiteratureKnown} + \textsc{RandomGeneric}
  \item \texttt{pentagon\_sweep.jsonl} --- \textsc{PentagonSweep}
  \item \texttt{polygon\_grid.jsonl} --- \textsc{PolygonGrid}
  \item \texttt{random\_products.jsonl} --- \textsc{RandomProducts}
  \item \texttt{acceptance.jsonl} --- Rejection sampling statistics
    (Section~\ref{sec:rejection-sampling})
\end{itemize}

All files are committed to the repository and regenerated after algorithm
changes.
