\subsection{Visualization of Reeb Dynamics}
\label{sec:visualization}

To build geometric intuition about Reeb flows on polytope boundaries,
we visualize $\mathbb{R}^4$ polytopes and their Reeb orbits via
stereographic projection to~$\mathbb{R}^3$.

\subsubsection*{Projection pipeline}

The visualization uses a two-stage projection:
\[
  \partial K \;\xrightarrow{\;\text{radial}\;}\; S^3
  \;\xrightarrow{\;\text{stereographic}\;}\; \mathbb{R}^3.
\]

\emph{Radial projection.}
The map $x \mapsto x / \lVert x \rVert$ sends $\partial K$ to~$S^3$.
This is well-defined since $K$ is a convex body containing the origin
in its interior, so every ray from the origin meets $\partial K$
exactly once.

\emph{Stereographic projection.}
% [TODO: JÖRN - verify conformality claim and stereographic projection formula
%  eq:stereo-proj. Agent-written from general knowledge.]
We use stereographic projection because it is conformal
(preserving angles locally) and maps great circles on~$S^3$
to circles or lines in~$\mathbb{R}^3$, so the polytope's
combinatorial structure remains visually recognizable.
Fix a north pole $n \in S^3$. For $y \in S^3 \setminus \{n\}$,
the stereographic projection sends $y$ to the intersection of the ray
from~$n$ through~$y$ with the tangent hyperplane to~$S^3$ at~$-n$.
In coordinates:
\begin{equation}
  \label{eq:stereo-proj}
  \pi_n(y) \;=\; \frac{y - \langle y, n \rangle \, n}{1 - \langle y, n \rangle},
\end{equation}
which maps $S^3 \setminus \{n\}$ conformally to~$\mathbb{R}^3$
(identified with the hyperplane $n^\perp$ via an orthonormal basis).

\emph{Pole singularity.}
Points near the north pole project to large radii.
The implementation clips geometry within an angular neighbourhood
of~$n$: a point~$y \in S^3$ is omitted when
$\langle y, n \rangle \geq (R^2 - 1)/(R^2 + 1)$,
where $R$ is a configurable clipping radius.
Line segments passing through this neighbourhood are split at the
boundary and only the exterior portions are drawn.
This produces visible gaps in edges and trajectories near the pole,
which is expected and does not indicate missing geometry.

\subsubsection*{Reeb orbits}

The visualization shows three types of trajectories,
all obtained from the algorithm's output
(Definition~\ref{def:reeb-orbit-polytope},
Lemma~\ref{lem:base-point-recovery}).

\emph{Minimum-action orbits.}
For each polytope, the algorithm (Algorithm~\ref{alg:ehz})
enumerates all certified solutions~$(S, \sigma, \beta)$
with $\beta_i > 0$.
Each solution determines a closed generalized Reeb orbit
via base point recovery (Lemma~\ref{lem:base-point-recovery}):
the linear system $N_S \cdot b = r$ (where $N_S$ collects the
outward normals of the facets in~$S$) is solved for
the offset $b = \gamma(0)$, and the breakpoints
$\gamma(t_k)$ at facet transitions are computed from~$\beta$
and~$\sigma$.
Solutions achieving the minimum action $c_\mathrm{EHZ}(K)$
are labelled as minimum-action orbits.
Several polytopes have multiple distinct minimum-action orbits
(Table~\ref{tab:viz-orbits}).

\emph{Higher-action orbits.}
Solutions with action above the minimum are included
when base point recovery succeeds
(closure error ${} < 10^{-6}$,
constraint violation ${} < 10^{-4}$).
Some higher-action orbits have underdetermined base point
systems and fail recovery
(constraint violation ${} > 10^{-4}$).
The total number of displayed orbits is capped at~20
per polytope.

\emph{Displaced trajectories.}
To illustrate how nearby Reeb trajectories twist relative
to a minimum-action orbit, we perturb the recovered base
point~$b = \gamma(0)$ by $\varepsilon \cdot v$, where $v$ is
a unit vector tangent to the starting facet~$F_{\sigma(0)}$
and perpendicular to the Reeb flow direction
(Definition~\ref{def:reeb-vectors}).
The displaced trajectory is then forward-simulated for the
same number of facet segments as the original orbit.
These displaced trajectories generally do not close:
the combinatorial facet sequence can diverge from the
original orbit's sequence even for small perturbations.

\subsubsection*{Observations}

The interactive visualization renders the eight known polytopes
from the dataset library and is available online at
\url{https://joernstoehler.github.io/msc-math/viz/}.
For each polytope, the user can toggle display of vertices, edges,
ridges (2-faces), and individual Reeb orbits, and
rotate the stereographic north pole.
Figures~\ref{fig:viz-hypercube} and~\ref{fig:viz-trajectories}
show representative screenshots.

Several qualitative features are visible:

\begin{itemize}
  \item On the hypercube $[-1,1]^4$, the two minimum-action orbits
    each visit 4 of~8 facets, reflecting the decomposition into
    two symplectic planes.
    The projected orbits form compact, nearly elliptical closed curves.

  \item On the simplex, all six minimum-action orbits visit all
    5 facets and achieve the same action ($0.25$),
    reflecting the full symmetry group of the simplex.

  \item The HK-O pentagon has at least 20 distinct minimum-action
    orbits (capped at~20 for display), all achieving
    action~$\approx 3.441$.

  \item On Lagrangian products, higher-action orbits frequently
    fail base point recovery (underdetermined linear system,
    high constraint violation), while minimum-action orbits
    recover reliably.

  \item Displaced trajectories visibly twist around the
    minimum-action orbit, with larger displacement~$\varepsilon$
    producing greater deviation.
    On the hypercube, displaced trajectories happen to close
    (the orbit family is stable under small perturbations),
    while on less symmetric polytopes they diverge.

  \item Ridges (2-faces) curve under the stereographic projection
    (Figure~\ref{fig:viz-hypercube}, right),
    giving visual evidence that great-circle arcs on~$S^3$ map to
    circles in~$\mathbb{R}^3$.
\end{itemize}

\subsubsection*{Implementation}

The visualization consists of a Rust export tool
(\texttt{viz\_export}) that computes all Reeb orbits via
the algorithm (Algorithm~\ref{alg:ehz}) and recovers their
base points (Lemma~\ref{lem:base-point-recovery}),
exporting the polytope skeleton and orbit breakpoints as JSON.
A browser-based viewer
(\texttt{experiments/\allowbreak visualization/\allowbreak viz/})
built with Three.js loads the JSON data and performs the
projection pipeline in JavaScript, rendering the result as an
interactive 3D scene.
Sampling along edges and ridges uses spherical linear interpolation
(slerp) on~$S^3$ to produce uniform angular spacing, which
stereographic projection maps to smooth~$\mathbb{R}^3$ spacing.
