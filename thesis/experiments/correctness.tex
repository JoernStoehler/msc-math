\subsection{Correctness Verification}
\label{sec:correctness}

Before using the computed capacities for experimental conclusions, we verify
that the implementations are correct. This section documents the mathematical
properties tested, the polytope subsets used, and the results.

All tests are implemented as automated Rust tests and run as part of the
continuous test suite. Capacities are pre-computed in release mode and cached
as a JSON fixture; the property tests then verify the cached values
in under one second.

\subsubsection*{Cross-algorithm validation}

On the overlapping domain (Lagrangian products), HK2017 and the billiard
algorithm should produce the same capacity. We verify this on three
datasets of increasing size:
\begin{enumerate}
  \item \textbf{Fixture} (3 Lagrangian products + scaled variants):
    Agreement within $10^{-8}$ relative error.
  \item \textbf{PentagonSweep} (361 points): Perfect agreement on all
    361 data points (relative error~$< 10^{-12}$).
  \item \textbf{PolygonGrid} (10 pairs, ${\sim}2300$ points): All 10 pairs
    have 100\% agreement (within~$10^{-8}$ relative tolerance).
    During development, the~$(4,4)$ and~$(4,6)$ pairs exhibited capacity
    discontinuities caused by a fixed-tolerance SVD rank detection in the
    shared KKT solver. After switching to gap-based rank detection,
    both pairs show smooth capacity curves and full cross-validation.
\end{enumerate}

All 10 polygon pairs show 100\% cross-validation with smooth capacity
curves, providing strong evidence that both implementations are correct
on their shared domain.

\subsubsection*{Conformality and invariance}

% Is this range sufficient to test the property thoroughly?]

For each base polytope in the fixture, we generate:
\begin{itemize}
  \item A scaled copy $\alpha K$ with random $\alpha \in [0.5, 2.0]$, verifying
    $c(\alpha K) = \alpha^2 \cdot c(K)$ and $\mathrm{vol}(\alpha K) = \alpha^4 \cdot \mathrm{vol}(K)$.
  \item A symplectomorphism image $MK + b$ with random $M \in \mathrm{Sp}(4)$,
    verifying $c(MK+b) = c(K)$ and $\mathrm{vol}(MK+b) = \mathrm{vol}(K)$.
\end{itemize}

Both properties hold to within $10^{-6}$ relative error on all tested
variants. The symplectomorphism matrices are generated via the Cayley
transform $(I - A)(I + A)^{-1}$ where $A \in \mathfrak{sp}(4)$, ensuring
the result lies in $\mathrm{Sp}(4)$ exactly.

\subsubsection*{Monotonicity}

For pairs of polytopes $(K_1, K_2)$ in the fixture, we compute the largest
$\alpha$ such that $\alpha K_1 \subseteq K_2$ by checking vertex containment.
On the 20 pairs with largest non-trivial $\alpha$, we verify
$c(\alpha K_1) = \alpha^2 c(K_1) \le c(K_2)$, combining conformality with
monotonicity. All pairs satisfy the inequality.

\subsubsection*{SVD gap threshold over-truncation}

The KKT solver uses a gap-based SVD rank detection: if the ratio of
consecutive singular values exceeds a threshold ($100{\times}$), the
smaller singular values are treated as null-space directions. As noted
in Section~\ref{sec:benchmark}, an LU fast path catches some valid
orbits that this gap truncation rejects.

To quantify the impact, we compared LU+SVD against SVD-only on
random polytopes at~$F = 7, 8, 9$ (10 polytopes each at~$F \le 8$,
5~at~$F = 9$):

\begin{center}
\small
\begin{tabular}{rrrrl}
\toprule
$F$ & Permutations & LU-only orbits & Rate & Capacity-optimal? \\
\midrule
7 &   23{,}650 & 26 & 0.11\%   & 0/26 \\
8 &  160{,}640 &  1 & 0.0006\% & 0/1 \\
9 &  628{,}320 &  1 & 0.0002\% & 0/1 \\
\bottomrule
\end{tabular}
\end{center}

The ``LU-only orbits'' are permutations where LU finds a valid solution
($\beta > 0$) but the SVD pseudoinverse (with gap-based rank truncation)
does not. In all 28 cases across three facet counts:
\begin{itemize}
  \item The last singular value is~$10^{-3}$--$10^{-2}$, with a gap
    ratio of~$100$--$600{\times}$ to the penultimate value---right at
    the detection threshold.
  \item The SVD pseudoinverse produces negative~$\beta$ components,
    so the orbit is correctly rejected on the SVD path.
  \item \textbf{None of the 28 LU-only orbits is capacity-optimal.}
    Comparing the orbit action~$Q$ against the computed capacity
    for each polytope, all LU-only orbits have strictly higher action.
\end{itemize}

The fraction of affected orbits \emph{decreases} with~$F$
(from~$0.11\%$ to~$0.0002\%$), which is reassuring: the
over-truncation does not accumulate at higher facet counts.

The LU fast path adds~$6$--$11\%$ wall-clock overhead
(Section~\ref{sec:benchmark}) but serves as a safety net:
if a future polytope class produces LU-only orbits that \emph{are}
capacity-optimal, LU would catch them while SVD-only would silently
return a suboptimal value. Until the gap threshold is replaced by a
more principled rank detection method, LU remains in the production
solver.

\subsubsection*{Debug-mode testing}

The HK2017 implementation contains extensive \texttt{debug\_assert!}
checks for internal invariants (index bounds, matrix dimensions, KKT
solution validity). These assertions are active in debug builds and
exercised on polytopes with $F \le 8$, where the exponential cost
remains manageable. For the rationale behind this facet-count limit,
see Section~\ref{sec:benchmark}.
