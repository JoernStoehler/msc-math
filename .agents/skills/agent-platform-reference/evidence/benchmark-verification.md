# Codex acquisition benchmark verification

On 2026-10-13, `GET https://api.github.com/repos/openai/codex/releases/latest` succeeded and still identified `rust-v0.162.1` (published 2026-10-09T19:44:51Z). The benchmark already present in this workspace is pinned to that release, so no new run was needed. The raw latest-release response is preserved in [`codex-latest-release.json`](codex-latest-release.json). The Git ref API reports an annotated tag object `7a078f6bb4ce0dc2a81408b334ce52979d92c603` (raw response: [`codex-release-tag-ref.json`](codex-release-tag-ref.json)); both retained Git checkouts resolve to peeled commit `092d3acd6bec3e3a14bdc7e7a2810ab628ab759d`. The tag commit is present in the clone and matches the archive tag version.

The copied [`benchmark-run.log`](benchmark-run.log) and [`benchmark-original.tsv`](benchmark-original.tsv) record successful serial timings: archive 17.494 s, depth-1 clone 10.983 s, sparse blob-filtered checkout 21.753 s. These include fetch plus extraction/checkout. The TSV's `on_disk_bytes` values came from `du -sk`, so they are 1 KiB-rounded allocation figures and include `.git` where present. Regular-file logical bytes sum `st_size`; symlink path length is listed separately; allocated bytes sum `lstat().st_blocks * 512` and can vary with filesystem/compression. Sparse checkout covers only `docs` and `codex-rs/core`, so its smaller worktree is not equivalent in content to the complete archive or shallow checkout. Git pack and `.git` sizes describe local stored metadata after checkout, not exact network traffic. No wire-byte instrumentation was enabled. Archive timing includes decompression; Git timings include checkout work. Because the methods ran serially and share caches, timings are single-run observations rather than general speed claims.

Reproduction: `bash scripts/benchmark_codex.sh rust-v0.162.1`. The script fetches/extracts the tag archive, shallow-clones the tag, then performs a depth-1 `blob:none` clone and sparse checkout of `docs` plus `codex-rs/core`. Use a clean output directory; the script refuses to overwrite existing method paths. The TSV it emits reports allocated directory size via `du`, not logical bytes or network transfer. Record interface-level transfer separately if wire costs matter.

## Implication for corpus acquisition

For a complete source snapshot, archive and shallow clone yielded identical file counts and logical worktree size in this observation. The archive was smaller in compressed payload than the locally retained Git pack bytes, while the shallow clone preserves Git metadata and can support later Git operations. Sparse checkout substantially reduced initial local checkout and metadata, at the cost of omitting most repository content and potentially fetching blobs later. None of these measurements establish a task-retrieval winner or document coverage: Codex repository docs include redirect/pointer stubs, so user-facing docs still need separate acquisition. Keep the benchmark decision about source acquisition separate from documentation mirroring and agent retrieval evaluation.
