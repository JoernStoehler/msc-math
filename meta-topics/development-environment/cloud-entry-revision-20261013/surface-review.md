Source delivery is separated from instruction loading; scoped archive identity is separated from base commit; task-specific tools, private inputs, review, return and workspace lifetime have explicit owners. No blocking contradiction found in the inspected contract. Two small guidance gaps matter before calling this usable across every named surface.

1. **Make shell-less entry explicit in AGENTS.** Candidate says search with `rg` before concluding absence and its quick commands presume a checkout/shell. Cloud workflow recognizes connector/chat-context access, but does not explicitly give the equivalent source-search obligation when shell/rg is absent. Add a short condition: use the available source/search tools, identify the inspected source and access limits, and do not claim a checkout or exhaustive search from retrieved excerpts. This is capability-conditional; ordinary Chat, Pro or Cowork must not be declared incapable of cloning/shell execution merely from their name.
2. **Preflight task-relevant owner closure and review return route.** The documentation archive example deliberately omits research-guide, docs/artifacts, topic/thesis owners and AGENTS.md.commentary.md. Some omissions apply even to a guidance-design assignment because commentary is triggered. It is correctly labelled incomplete, but a recipient can reach missing owners immediately. Add an explicit requirement to include the owners that the actual task triggers, or list them as unavailable and give the receiving coordinator their retrieval obligation. Likewise name the review/integration owner in every standalone chat assignment: message-review requires a separate native reviewer, so a surface without one must return a pending draft to an established coordinator route. The runbook already does this; the general workflow should make the same assignment concrete before work begins. No need to duplicate a catalog or deliver the whole repository.
