# Working card for Jörn

Keep this open as a glanceable habit aid. It is not project authority or agent
instructions.

## Before starting work

- Name the terminal artifact or decision, not merely the topic.
- State the current crux, Jörn-only authority boundary, and cheapest useful
  next observation.
- Use a persistent goal only for a genuinely multi-turn terminal objective.
- Split independent deliverables into separate roots early; do not make one
  root carry an avoidable portfolio of work.

## While work is active

- Do not keep session state in working memory. Ask for a cold recap after a
  context switch.
- Compact, hand off, or start a fresh root before a long serial history becomes
  the work.
- If a plan has gone wrong, stop and re-plan from the objective instead of
  repairing the old plan incrementally.
- Let agents and clients monitor agent-doable state. Spend Jörn's attention on
  choices, private context, mathematical cruxes, and review.

## Before leaving a thread

- Externalize the current artifact, evidence, uncertainty, owner, authority
  boundary, and exact resume point.
- Mark the work accepted, rejected, parked with a reopen condition, or still
  active. Do not leave “probably finished” as implicit state.
