consequential failure modes. Strengthened checks:

   claim, a reviewer walks its whole argument and locates definitions,

   promises unsupported. Keep an eleven-area ledger tied to the exact candidate:
   retained claim, source/rendered location, support owner, required explanation,

   window. Before a lane executes, name the gap, closest existing result it must
   improve, rival explanation/control, and section or continuation packet it would
   strengthen. Stop redundant searches; do not call finite negative search a theorem.

or substitutes for Jörn's prose/PASS judgment. Research remains a legitimate

## Dependencies and allocation proposal

P1–P5 couple to P11 through source edits and rendered interfaces. P2 and P5
share HKO appendix references; one owner must integrate that overlap. P5 depends
on P6/P7 for truthful numerical examples and availability. P6 and P7 share
producer/API contracts; assign disjoint mutations and exchange exact artifacts.
P8 depends on P11 for a final candidate identity, but a rights/data inventory is
useful early. P9 is independent of mathematical results; applying skill changes
mid-run can change agent exposure, so proposed execution records the baseline
and avoids silently replacing active workers' instructions. P10 need not change
the manuscript: new results remain separate until thesis inclusion is selected.

Proposal: bounded parallel ownership, with discovery and source checks first,
then execution justified by them; reserve the final approximately 90 minutes
for independent challenge, fan-in, PDF/evidence inspection and handoff. This is
an agent allocation estimate, not a dollar/token threshold or promise that every
packet finishes. A genuinely unresolved result stays unresolved; it does not
become a success because the window ended. Stop a research lane if it only
duplicates retained results; preserve a useful falsifier rather than starting
an indiscriminate larger batch. Paid APIs, external messages and publication
are outside the proposal unless Jörn expressly adds them.

Alternatives: emphasize robust thesis/code/reproduction repairs; emphasize new
research with fewer source changes; or run a balanced portfolio including the
selected workflow delivery. The balanced portfolio is the current recommendation
because different branches can make useful progress independently. It risks
coordinator overload; owners and fan-in capacity must be selected accordingly.
