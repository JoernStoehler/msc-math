# Iterate internally, not in front of the user

Session: 2026-04-09, RESULTS.md revision

## Incident

The agent went through ~8 rounds of visible corrections with Jörn: wrong first draft → wrong second draft → reviewer findings presented to Jörn → corrections to process description → corrections to compressed text → more corrections. Each round consumed Jörn's time and attention.

The agent had subagents available for iteration but used them only for verification (correct numbers? missing items?) rather than for the harder question: "is this the right thing to write?"

## Actionable

Before showing work to Jörn:
- Use subagents to catch problems YOU can evaluate (accuracy, consistency, dropped content)
- Process subagent feedback yourself — fix what you agree with, discard what you don't
- Never present subagent findings to Jörn or ask him to adjudicate between your view and a reviewer's
- If you reference a reviewer's opinion, either share (agree with) it and act on it, or don't mention it

The goal: Jörn sees one well-considered proposal, not a sequence of drafts.
