# API agents and SDKs: execution model before product name

**Reviewed:** 2026-10-13 against locally acquired OpenAI developer docs, OpenAI Agents SDK docs, and Anthropic Claude API/Claude Code docs. These are documentation claims, not runtime probes. “Agent,” “SDK,” and “API” do not imply the same owner for the tool loop, session state, or compute environment.

## OpenAI

- **Agents SDK:** A code-first library track for an application that owns deployment, tool implementations, state storage, and approval decisions; the SDK runs the agent loop and invokes the configured tools. OpenAI docs describe SDKs for TypeScript and Python and cover tools, orchestration/handoffs, sandboxing, guardrails, results, tracing, and evaluation. This is distinct from a service-hosted harness. Source: [Agents SDK guide](https://developers.openai.com/api/docs/guides/agents/sdk); local mirror: `corpus/articles/openai/openai-api/openai-api-api-docs-guides-agents-sdk.md`. The Python SDK reference is mirrored under `corpus/articles/openai/openai-agents-sdk/`.
- **Agents API:** OpenAI docs describe a managed Codex harness, with OpenAI handling sessions, orchestration, context compaction, and recovery; the application configures the agent, supplies tools, and chooses an environment. Environments include none, OpenAI-hosted, and self-hosted modes with different compute/filesystem ownership. App code still handles its function tools and lifecycle work where applicable. Sources: [Agents API overview](https://developers.openai.com/api/docs/guides/agents-api/overview), [Architecture](https://developers.openai.com/api/docs/guides/agents-api/architecture); local mirrors: `corpus/articles/openai/openai-api/openai-api-api-docs-guides-agents-api-overview.md` and `corpus/articles/openai/openai-api/openai-api-api-docs-guides-agents-api-architecture.md`.
- **Responses API tools:** A lower-level request/response integration that exposes model and tool calls through Responses API. The Skills guide separates this tool mode from Agents API sandbox-directory discovery. Do not infer durable session management or a managed autonomous agent harness simply from using a Responses API tool. Source: [Skills guide](https://developers.openai.com/api/docs/guides/tools-skills); local mirror: `corpus/articles/openai/openai-api/openai-api-api-docs-guides-tools-skills.md`. For general Agents API/SDK/Responses comparisons, see the official [Agents guide](https://developers.openai.com/api/docs/guides/agents).

## Anthropic

- **Claude API tool use with a Client SDK:** Model output can include `tool_use` blocks. For client tools, the application executes the requested function, returns a matching `tool_result`, and continues the Messages conversation. Anthropic server tools execute on Anthropic's side. The beta SDK Tool Runner automates request/result looping and state handling for supported SDKs; use manual tool-call handling when custom execution, approval, or control is needed. Sources: [Tool use overview](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview), [Handle tool calls](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls), [Tool Runner](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-runner); local mirrors under `corpus/articles/anthropic/claude-api/`.
- **Claude Agent SDK:** Anthropic describes it as running the Claude Code binary and providing Claude Code's tools, agent loop, context handling, permissions, sessions, hooks, and related features to a Python or TypeScript application. Filesystem features depend on effective SDK settings: omitting `settingSources` reads user/project sources in the inspected current docs, while explicit `settingSources: []` excludes those filesystem features; repo skill files alone do not override that choice. Source: `claude-code-docs-en-agent-sdk-skills` and `claude-code-docs-en-agent-sdk-claude-code-features`. The application operates the process and supplies the API key; this is not ordinary Claude Code CLI interaction, nor just a Messages Client SDK wrapper. Sources: [Agent SDK quickstart](https://code.claude.com/docs/en/agent-sdk/quickstart), [Agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop); local mirrors: `corpus/articles/anthropic/claude-code/claude-code-docs-en-agent-sdk-quickstart.md` and `corpus/articles/anthropic/claude-code/claude-code-docs-en-agent-sdk-agent-loop.md`.

## Selection and evidence boundaries

Choose by the owner of orchestration/state and compute: application-owned SDK loop; provider-managed session/harness; or direct model API/tool-call loop. Then verify what the chosen environment can access, who executes each tool, where files and credentials live, how approval is enforced, and who pays for model/tools/compute. Product docs describe intended mechanics; validate the actual deployed library/API version and configuration before relying on implementation details.

The corpus currently mirrors the OpenAI Agents API and SDK guides, the Python Agents SDK reference, Anthropic Messages tool-use and Tool Runner docs, and Claude Agent SDK docs. It does **not** include a locally verified Anthropic Managed Agents reference in this subset. Claude Agent SDK documentation links to Managed Agents, but that link alone is not evidence for their operational behavior. Consult current official docs before making Managed Agents claims.
