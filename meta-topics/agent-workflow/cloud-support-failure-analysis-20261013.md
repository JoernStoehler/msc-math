## A resource strategy that changes the decisions

The remedy is not simply “plan less” or “use more agents.” Planning, source consultation, review and integration have real indirect value when they change a consequential decision. Greedy execution can spend the entire allowance on the wrong route; prolonged analysis can consume it without delivering the result. Allocation must consider both.

For each stage, the coordinator should identify the decision or deliverable, the evidence needed to finish it, its allocation from the shared envelope, and the remaining path to delivery. Keep a reserve for integration, required review and readable delivery. There is no evidence-based universal percentage for that reserve; choose it for the actual package and revise it visibly when the path changes.

Before another investigation, ask: **What plausible finding would change our action? Is that change valuable enough to justify this investigation's total cost?** Before more execution, ask whether a small prerequisite check would avoid an expensive failure. Stop when the next step is lower value than another selected branch or consumes the delivery reserve. This is a judgment about expected value, not a prohibition on unsuccessful experiments.

Parallelism reduces wall time only when the branches are genuinely independent and can be integrated. For the proposed tool setup, the idealized path is shared preparation plus the slowest independent branch plus integration. Package-manager locks, CPU, memory, network and human decisions can lengthen it. Aggregate resources still add across branches. A large coordination queue can erase the apparent benefit.

Use real elapsed checkpoints and available scoped usage observations. Track root attention, workers, relays and review together; do not count time twice across overlapping branches or copied forks. When a worker hits a blocker, it returns the supported alternatives and decision needed under the same envelope. Its short cap does not grant another short cap automatically.

A hard cap can itself encourage optimizing a cheap proxy: a short report, a passing component or a premature completion claim. At checkpoints, identify the user-valued result already deliverable, the unresolved dependencies and the capacity needed to finish. Budget compliance is a constraint, not the outcome.

Ask you for help when your information or authority can change the route: a real cutoff, whether a cloud environment survives, an essential access grant, a substantive spending decision, or a tradeoff in accepted coverage. Recover source facts independently. Bundle related decisions with enough context; do not ask you to dispatch every toolchain, diagnose the model, or repeat settled goals.

Three checks make breadth more useful than an idea count:

1. **Counterfactual repair:** if the browser worked, would the reference skill, other tools and continuation obligations still be unfinished? Yes. If every tool installed, could the source or return route still fail? Yes. If the next context were fresh, could the same unbounded follow-up pattern recur? Yes. Each remedy must be assessed against the whole task.
2. **Contradiction check:** compare claims of goal uncertainty with the actual user instructions; claimed permission with the actual grant; a “pending” request with its later withdrawal; and a “working” environment with its dated execution evidence.
3. **Behavioral check:** assess the next decisions after a correction or consultation, not only the agent's account of what it learned. Trace consulted source → decision → action or explicit deferral → verification → cost. Preserve negative commitments such as stopped execution and withdrawn requests across handoffs. Use different roles and actual sources to reduce shared blind spots; another instance of the same model is useful scrutiny, not independent proof of correctness.

Exhaustive analysis would require simulating future agents and you. Useful completeness instead means covering material obligations, competing routes, observed failures, evidence limits, ownership and resource choices, while explicitly assigning discoveries that can only occur later. That is the standard applied here.
